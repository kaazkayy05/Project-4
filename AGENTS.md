# Project Instructions

This is a collaborative Godot project. These instructions apply throughout
this repository.

Do not import another project's design, tasks, art direction, milestones,
mechanics, or ownership assignments.

## 1. PERMISSION REQUIRED FOR ALL CHANGES

- Never edit, create, delete, rename, move, overwrite, or replace files
  without my explicit approval first.
- Before changing anything, list the exact file paths, explain what will
  change and why, and show the proposed edits.
- Wait for my response before applying changes.
- Approval covers only the specific files and changes I authorize.
- Do not treat approval for one task as approval for extra changes.
- Reading relevant files is allowed without editing them.

## 2. PROTECT TEAMMATES' WORK

- Never edit or otherwise modify teammates' files without asking me
  beforehand and receiving clear, explicit permission for the exact
  files and proposed changes.
- Do not rewrite, refactor, reorganize, or optimize teammates' code.
- Preserve existing interfaces, signals, and integrations.
- If a task requires editing a teammate-owned file, stop, identify its
  exact path, explain why, and show the proposed edits. Ask for permission
  and wait for my clear approval before changing it. Silence or approval
  for another task does not count as permission.
- Never overwrite teammates' work to resolve conflicts.
- Ask me for ownership assignments. Do not invent them or copy
  assignments from another project.

## 3. PROTECT MY WORK

- Preserve existing functionality unless I authorize changing it.
- Prefer small, targeted edits over replacing entire scripts.
- Do not modify unrelated code, even within an approved file.
- Do not delete functionality because it appears unnecessary or
  duplicated. Explain the issue and ask first.
- Preserve manual edits and changes made in other sessions.

## 4. STRICT TASK SCOPE

- Work only on the exact task I request.
- Do not add extra features, dependencies, assets, UI, tests, or systems
  without approval.
- Report unrelated problems without fixing them.
- Inspect existing functionality before proposing a new system.
- Do not change the startup scene, Autoloads, input mappings, renderer,
  plugins, export presets, or shared project settings without explaining
  the consequences and obtaining approval.
- Follow the project's supplied mechanic specifications exactly. Do not
  silently change inputs, distances, durations, thresholds, or behavior.
- Ask when requirements are ambiguous.
- Do not import rules or mechanics from my other projects.

## 5. GIT AND REPOSITORY SAFETY

- Read-only Git inspection is allowed.
- Never stage, commit, push, pull, fetch, merge, rebase, reset, restore,
  stash, or discard changes without explicit approval.
- Never create, switch, rename, or delete branches without approval.
- Never resolve merge conflicts automatically.
- Never stage unrelated files.
- Never change remotes, workflows, deployment configuration, repository
  visibility, or collaborator settings without approval.
- Never force-push or use destructive commands without explicit
  authorization for that exact action.
- Work only in this repository, not its parent or another project.

## 6. RUNNING TOOLS AND VALIDATION

- Explain proposed validation commands before running them.
- Ask before launching commands that generate or modify files,
  including Godot imports and generated metadata.
- Do not install software, add dependencies, download assets, or publish
  the project without approval.
- If testing reveals another required code change outside the approved
  scope, report it and ask before applying it.
- Clearly distinguish checks actually performed from checks I still
  need to do manually.

## 7. REQUIRED WORKFLOW

For each task:

1. Inspect relevant files and applicable instructions.
2. Identify the exact files requiring changes.
3. Explain the smallest proposed solution.
4. Show the proposed diff or full contents for new files.
5. List any commands and validation requiring approval.
6. Ask for explicit permission and stop.
7. Apply only the approved changes.
8. Perform only approved validation.
9. Show the final diff and report the results.
10. Ask before expanding the scope.

## 8. FINAL RULE

When uncertain whether an action is authorized, do not change anything.
Ask me first.
